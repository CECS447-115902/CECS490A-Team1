## How to use this file with the hub

| Hub field | What goes in it |
|---|---|
| Task ID | Auto-generated by the hub. Our ID (e.g. `SW-001`) goes at the start of the **Task title** so cards can be searched and matched to branches. |
| Status | BACKLOG, THIS WEEK, IN PROGRESS, BLOCKED, or DONE |
| Task title | `<ID> <title>` |
| Accountable owner | One person, even for team tasks |
| Due date | The committed date. Changing it later needs a **reason and a recovery action** in the hub |
| Definition of done | Copy as written; it must be checkable by someone else |
| Evidence link | Required before moving to DONE. Use the **PR link** for repo work (it shows the commits and attached logs/photos), or a OneDrive/photo link for purchases and meetings |
| Notes / blocker | Planned branch name, dependencies, and anything blocking the card |

## How branches work

Branch names follow the README convention `<area>/<card-id>-<topic>`. They are **planned**: a branch is created only when someone starts the card, from an up-to-date `main`:

```
git switch main
git pull
git switch -c fw/sw-001-lora-p2p
git push -u origin fw/sw-001-lora-p2p
```

Each branch merges through a pull request and is deleted after merging. Don't create branches ahead of time. Keep the `<area>/<card-id>-` prefix so the PR traces back to the card.

Area prefixes: `fw/` firmware · `hw/` schematic, PCB, BOM · `docs/` design docs, proposal, reports · `ui/` LVGL screens · `test/` test runs and logs · `app/` iOS app (if OPT-07 goes ahead)
